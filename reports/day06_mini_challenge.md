# Day 06 — Mini Challenge: Ch.-B. 코드 OCR 검사

## 1. 실습 내용

본 실습에서는 제품 이미지 6장의 SN을 숫자 13자리로 검사했다. Mini Challenge에서는 별도로 준비한 제품 이미지 4장을 사용해 `Ch.-B.` 뒤에 인쇄된 코드를 읽었다. 이번 코드는 숫자뿐 아니라 영문과 하이픈이 섞여 있어 OCR Whitelist와 문자열 검사 규칙을 바꿔 적용했다.

제품 이미지에서 코드 부분만 ROI로 선택하고, Tesseract OCR 결과를 이미지에 실제로 인쇄된 값과 비교했다. SN 검사에 사용한 `day06-ocr-v1.0`은 수정하지 않았다.

## 2. 첫 번째 OCR 결과

처음에는 영문 대문자·숫자·하이픈을 허용하는 정규식 `^[A-Z0-9-]+$`를 사용했다.

| 이미지 | 실제 코드 | OCR 결과 | 형식 검사 | 정확히 일치 |
|---|---|---|---|---|
| `0185973818825_side.png` | `NA679903-8A` | `NA679903-8A` | 통과 | O |
| `0386316000696_side.png` | `TI776224-2D` | `TI776224-20` | 통과 | X |
| `0635619134582_side.png` | `KW156489-8R` | `KW156489-8R` | 통과 | O |
| `0924467469402_side.png` | `ER935556-3V` | `ER935556-3V` | 통과 | O |

OCR 결과는 4장 중 3장이 실제 코드와 일치해 정확도는 75%였다. `TI776224-2D`에서는 마지막 영문 `D`를 숫자 `0`으로 읽었다. 그런데 기존 정규식은 숫자 `0`도 허용하기 때문에 이 결과를 형식상 정상으로 판단했다.

## 3. 실패 이미지 전처리 비교

오류가 발생한 `0386316000696_side.png`에서 코드 ROI를 다시 선택하고 Original, Gray, CLAHE, Otsu, CLAHE+Otsu를 비교했다. 전처리별 OCR 설정과 4배 확대 조건은 동일하게 적용했다.

| 전처리 | OCR 결과 | 실제 코드와 일치 |
|---|---|---|
| Original | `11776224-20` | X |
| Gray | `T1776224-20` | X |
| CLAHE | `TI776224-20` | X |
| Otsu | `TIT76724-20` | X |
| CLAHE + Otsu | `T1778224-20` | X |

5가지 모두 정확한 코드로 읽히지는 않았다. CLAHE에서는 마지막 글자만 `0`으로 잘못 읽고 나머지 부분은 일치했지만, 다른 전처리에서는 앞부분의 `T`, `I`, 숫자도 잘못 인식하는 경우가 있었다.

다만 이번 비교에서는 ROI를 다시 지정했으므로 처음 Mini Challenge와 ROI가 완전히 같다고 볼 수는 없다. 따라서 이 결과만으로 전처리 효과를 단정하지 않고, 이 이미지에서는 시험한 5가지 방법 모두 정확한 인식에 실패했다고 기록했다.

## 4. Regex 형식 검사 수정

처음 사용한 `^[A-Z0-9-]+$`는 영문, 숫자, 하이픈의 종류만 확인해서 마지막 자리가 `0`이어도 통과했다.

이번에 확인한 코드 4개는 모두 영문 2자리, 숫자 6자리, 하이픈, 숫자 1자리, 영문 1자리의 형태였다. 그래서 Mini Challenge 결과를 대상으로 다음 정규식을 추가로 적용했다.

```python
r"^[A-Z]{2}[0-9]{6}-[0-9][A-Z]$"
```

| 실제 코드 | OCR 결과 | 수정한 형식 검사 | 최종 판정 |
|---|---|---|---|
| `NA679903-8A` | `NA679903-8A` | 통과 | OK |
| `TI776224-2D` | `TI776224-20` | 실패 | NG |
| `KW156489-8R` | `KW156489-8R` | 통과 | OK |
| `ER935556-3V` | `ER935556-3V` | 통과 | OK |

수정한 정규식에서는 `TI776224-20`이 마지막 영문 자리 조건을 만족하지 못해 NG로 분류됐다. 다른 3개는 정상적으로 통과했다.

다만 이 정규식은 이번에 확인한 이미지 4개의 코드 형식을 기준으로 만든 것이다. 제품의 공식 코드 규격을 확인한 것은 아니므로 모든 `Ch.-B.` 코드에 같은 규칙을 적용할 수 있다고 보지는 않았다.

## 5. 결과 정리

Mini Challenge의 OCR 정확도는 4장 중 3장인 75%였다. 전처리 5가지를 적용한 추가 실험에서도 잘못 읽힌 `D`를 정확하게 복구하지는 못했다.

대신 코드의 자리별 형식을 검사하도록 Regex를 수정하면서, 이전에는 형식 검사를 통과했던 `TI776224-20`을 걸러낼 수 있었다. OCR 인식률 자체가 올라간 것은 아니지만, 잘못 읽힌 문자열을 정상 코드로 처리하는 문제는 이번 4장에 대해 확인할 수 있었다.
